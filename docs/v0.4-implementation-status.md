# v0.4 development status

This checkout contains a verified Python baseline and an experimental Rust
foundation. **It is not a complete v0.4 runtime or a release candidate.** The
installed Python entry point remains the production daemon. Do not migrate a live
installation to v6 yet: Python correctly refuses that schema, and Rust does not
yet provide the replacement daemon services.

The corrected implementation plan in the task supersedes the earlier RST design:
attachments use schema v4, scoped fetch v5, and Rust additions v6; campaign GitHub
operations must use existing owner `gh`/SSH authentication. No new token, GitHub
App, deploy key, or reviewer identity is introduced.

```sh
node --test tests/dashboard.test.cjs
python scripts/verify_baseline.py
PYTHONPATH=spec python scripts/capture_gates.py

cargo fmt --all --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

Rust requires 1.88 or newer with the locked dependencies. The experimental CLI
requires explicit paths; use disposable copies of the database/configuration,
with the copied configuration's `state.path` pointing to the copied database:

```sh
cargo run --bin fridica -- check-config --config /tmp/config.toml
cargo run --bin fridica -- migrate --database /tmp/state.sqlite3 \
  --config /tmp/config.toml --dry-run
cargo run --bin fridica -- assets --list
cargo run --bin fridica-overseer -- plan --input /tmp/campaign-item.json
```

The v0.4 configuration additionally rejects a control socket inside any local
workspace and an unusably long XDG runtime socket path. These checks enforce the
planned control-file isolation. They are explicit v0.4 hardening, not claims of
identical acceptance for those previously accepted Python configurations.
