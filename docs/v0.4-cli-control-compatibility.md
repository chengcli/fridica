# Step 2 CLI and control compatibility audit

Audited against `spec/fridica/cli/main.py`, `spec/fridica/control/api.py` and
`spec/fridica/control/views.py` on 2026-09-29. This is checkout compatibility
accounting. It does not enable active CLI startup or certify installed artifacts,
actual backend versions, complete replay, or live Slack operation.

## CLI inventory

All eleven frozen top-level command names were reviewed. Ten are implemented;
`dashboard` is explicitly deferred by the owner. New experimental commands are
additive and do not replace the existing Python launcher.

| Frozen command | Rust behavior and evidence |
| --- | --- |
| `init` | Private starter config and companion assets, refuses overwrite. `tests/setup.rs`; v0.4 template and atomic publication are deliberate changes. |
| `configure` | Existing manual IDs, `--detect`, repeated channel names/IDs and `--config`; explicit selection before durable edit. `tests/setup.rs`. |
| `doctor` | Configuration and all configured targets, auth/protocol/auto-review checks; bounded fixed diagnostics, JSON and timeout options added. `tests/doctor.rs`. Real target conformance remains a deployment gate. |
| `start` | `--config` and `--observe-only` preserved. `--check-ready` added. Bare `start` runs the daemon; `--observe-only` is the opt-in observer (`--active` and the owner deployment record were removed on 2026-09-29/30). Readiness and doctor rerun before active startup. `tests/daemon_cli.rs`, `tests/startup_readiness.rs`. |
| `dashboard` | Deferred serving, CLI and redesign; retain Python server and JavaScript regressions. |
| `status`, `machines` | Existing JSON views through the authenticated daemon socket. |
| `threads [id] [action]` | List/detail plus pause, resume, close, archive, restore, clean. Owner pauses require owner authority; effects commit before acknowledgement. |
| `workers [id] [interrupt\|stop]` | Existing list/control dispatch; an ID without an operation still lists, matching Python. |
| `approvals [id] [once\|session\|deny]` | Existing list/decision dispatch; an ID without a decision still lists. |
| `outbox [id]` | List failed/ambiguous posts or explicit retry. Nonpositive IDs are rejected rather than treating zero as a list request. |

`tests/control_transport.rs` runs all **21 frozen control-command request shapes**
through the real Rust binary and a local Unix server. Capture with
`PYTHONPATH=spec python scripts/capture_control_cli.py`; this uses synthetic Python
configuration and a stub client, without credentials or services. Method, target,
body and exit status are compared. Rust deliberately omits Python's `actor` body
hint: authenticated peer/capability identity supplies authority.

Control commands preserve exit **2** for invalid input/configuration, **3** for an
unavailable daemon, and **4** for explicit HTTP rejection. Lost or malformed
responses also use 3; effects may already have committed. The client does not
retry, print response bodies as diagnostics, or infer that an uncertain mutation
failed. Reuse instruction client IDs and inspect durable state before an explicit
retry. Startup config/token errors use 2; failed diagnostic checks and the active
launch gate remain nonzero operational failures. `--socket` and private
`--capability-file` are additive connection options.

## Control route inventory

All **18 frozen method/path patterns** are present. Existing nine frozen JSON
view projections compare legacy keys and ordering; additive v6 keys are allowed.
The table names additional runtime evidence, not a claim of full HTTP byte parity.

| Method/path patterns | Rust evidence |
| --- | --- |
| `GET /status`, `/threads`, `/threads/{id}` | Control transport projections; `control_views_notes_approvals_and_retry_use_durable_state` and authenticated runtime fixtures. |
| `GET /attention/threads` | Paused and active-blocked threads remain visible outside the recent page; frozen view corpus. |
| `POST /threads/{id}/notes` | Revision compare-and-set, owner identity, transactional audit, late-parent fencing; runtime note/control tests. |
| `POST /channels/{channel}/instruct` | Added: owner instruction to a configured channel's most recent thread; channel ID or startup-recorded name. |
| `POST /threads/{id}/{action}` | Six lifecycle actions plus `instruct`; owner pause protection, instruction validation/idempotency, cleanup/restart and restore fencing. |
| `POST /threads/{id}/delegate`, `/post`, `/driver`, `/workers/{worker}/stop`; `POST /channels/{channel}/post` | Added (fridica#130): the [external-driver surface](external-driver.md); strict bodies, owner only, limits and the egress gate as for the parent. Runtime-flow and actor tests. |
| `GET /workers`, `/jobs`, `/machines` | Legacy worker/process/job/machine views, bounded lists and configured placement. Runtime and frozen-view tests. |
| `POST /workers/{id}/{op}` | Interrupt/stop through the durable supervisor; owner-only, pending cleanup visible, no resurrection. Runtime worker-control tests. |
| `GET /approvals`, `POST /approvals/{id}` | Owner decisions, supported decision strings, missing/settled requests and durable wakeups. Runtime and approval tests. |
| `GET /outbox`, `POST /outbox/{id}/retry` | Safe metadata/file indicators, explicit retry only, dependency recovery and ambiguous sends. Runtime/outbox tests. |
| `GET /activity`, `/config` | Audit and safe configuration views, no replay payloads or attachment blobs. Control/runtime tests. |
| `PATCH /config/parent`, `/config/limits` | Owner-only durable edits, validation, comments, atomic file replacement and snapshot reconciliation. Configuration/runtime/composition tests; see [live configuration semantics](v0.4-live-configuration.md). |

Additive routes provide obligations, explicit historical backfill and owner
closure. They do not run backfill implicitly. MCP/report/campaign APIs and service
printing belong to later deliveries and are not declared complete by this audit.

Rust rejects unknown body/query fields, duplicate query keys, unsafe path segments,
invalid revisions and list limits outside 1–1000. Error responses use fixed codes;
legacy free-form error prose is not preserved. Most lists default to 100 (activity
200); attention selection remains unpaged. Responses are size-bounded. Body actor
hints cannot grant authority, and read-only capabilities cannot mutate state.
Legacy automatic-pause settings are intentionally not editable; attention settings
and isolation inventories currently require restart. These are declared safety and
v0.4 behavior changes, with no automatic retry of ambiguous operations.

Items 4–5 are complete for step 2: candidate commands/routes have been accounted
for and the regression ledger (removed with the v0.3 sources on 2026-09-30) assigns every frozen
case scoped evidence or specific retention. Historical and deployment validation remain
separate delivery gates; dashboard remains deferred.
