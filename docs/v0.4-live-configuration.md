# Experimental live configuration editing

The Rust control API supports authenticated **owner-only** edits. These are
available in the shared observer/active library composition. A custom library runtime must install its pure parent adapter
factory with `Runtime::with_configuration_editor`, retaining the original
`LoadContext`. Hosts with injected loading context can also use
`with_configuration_context`. Without a factory, edits return HTTP 503.

| Route | Editable fields |
| --- | --- |
| `PATCH /config/parent` | `backend`, `model`, `triage_model`, `reasoning_effort` |
| `PATCH /config/limits` | `max_delegations_per_turn`, `max_workers_per_thread`, `max_jobs`, `job_timeout`, `worker_idle` |

Bodies are JSON objects, such as `{"max_jobs":2}`. Unknown fields and invalid
values return HTTP 400. Overseer and read-only desktop credentials cannot edit
configuration. The v0.3 automatic-pause fields `max_wait_replies` and
`max_no_progress` are intentionally rejected; v0.4 uses attention streak signals.
The shared dashboard displays only fields supplied by the connected runtime, so
its Python compatibility is retained without submitting removed fields to Rust.
Attention thresholds, inventory, policy, Slack scope and other settings are not
editable through these routes.

Edits use the real configuration validator, preserve TOML comments, and replace a
private (0600) file atomically after syncing its contents. The containing directory
is synced before acknowledgement. The file must still match the daemon's loaded
fingerprint immediately before replacement. A private sibling edit-lock file
serializes Fridica writers, including offline setup commands. Edits that alter inherited settings
outside the requested fields are refused. For example, changing the parent backend
requires restart if machine backends implicitly inherit that value; explicitly
configured machine backends permit an independent parent change.

The runtime finishes its current pass before applying an edit, rebuilds the parent
and thread scheduler with the new snapshot, and updates worker admission settings.
Owner pause controls remain available during the wait. Existing jobs keep their
admitted configuration/deadline; subsequent admissions use the new settings.
Existing approval-broker reload behavior cancels pending approvals. Pauses are
preserved. Editing an observer does not start models, workers or posts.

SQLite records the old/new fingerprints before file replacement. It records the
outcome and service configuration fingerprint only after the runtime snapshots
agree; source text and credentials are
not included in configuration journal entries. A lost control response does not
undo the edit. Consult `GET /config`, `GET /status` and the activity audit before
retrying an uncertain request.

After an interruption, the next pass reconciles a matching replacement before
starting new parent/worker work. Startup adopts an exactly matching new file, or
records `not_applied` if replacement never happened. Unexpected file contents
block reconciliation instead of being overwritten. HTTP 409 means the update was
refused or still needs reconciliation; the `configuration_edit` and
`configuration_reconciled` audit events expose intent and outcome. Resolve a file
conflict using the known prior or intended file before restarting; there is no
automatic overwrite or rollback. Keep external file edits separate from live API
edits; arbitrary editors do not participate in the daemon's serialization.

These guarantees have local fixture coverage, not deployment-host or historical
replay evidence. No schema bump or active-launch admission change accompanies them.
