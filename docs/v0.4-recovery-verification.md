# Checkout recovery and replay verification

This is the checkout evidence for active-launch milestone 4 (delivery step 3),
reviewed 2026-09-29. It does not certify a live Slack deployment, installed
backends, or historical corpus parity. Active Rust CLI startup remains gated;
candidate packaging is the next checkout task.

## Deterministic comparison

`tests/runtime_flow.rs::complete_ordered_runtime_tapes_replay_every_durable_column_without_exclusions`
records fresh synthetic adapter calls and compares them with nine committed
[tapes](../tests/corpus/runtime/README.md). It then runs the same runtime from a
fresh database using the recorded results. Both runs must match every snapshot
and consume the complete ordered tape. Requests, typed failures, context,
worker completions and delivery outcomes are retained. Concurrent completions
are replayed in recorded order, even when futures are polled in another order.
Incomplete tapes, duplicate IDs, orphan completions and invalid ordering fail.

Each named checkpoint reads all SQLite tables and columns in one transaction:
verdicts, inbox/outbox effects and ordering, jobs, worker/session transitions,
obligations, reservations, audit and boundary records. No state field is waived.
Clocks and IDs are injected. Each fixture explicitly rebinds only its temporary
root and corresponding configuration fingerprint. The capture switch is opt-in;
ordinary verification never rewrites expected data.

Scenarios cover successful direct reporting, ambiguous delivery, rate limits,
one execution retry with session reuse, owner pause/resume, parent failure,
observe-only, unconsumed results after restart, and uncertain sends after restart.
An additional test reopens SQLite while a peer result is throttled, preserves
owner instructions, and executes twelve concurrent passes at the due time. It
checks one report, no repeated worker, answered obligation and no reserved slot.

Frozen Python differential fixtures retain their declared projections and
fixture-specific exceptions. These include the three daemon flows, delivery
ordering, parent behavior, rendering and lifecycle transitions. The new tapes
prove exact **Rust** runtime repeatability for their scripted boundaries; they do
not claim Python and Rust wire envelopes are identical or that synthetic
attention responses were predicted by history. Real protocol envelopes,
attachments, catch-up/ACK ordering, approvals, disconnects and process behavior
also retain their dedicated subprocess and fake-service tests.

Historical corpora remain absent. Capturing/redacting them and evaluating only
supported assertions remains a release-evidence requirement. All 389 Python
regressions remain retained; the [ledger](v0.4-regression-accounting.md) links new
scoped evidence without retiring them.

## Recovery fixes and fault evidence

Migration now uses the shared configuration writer lock and checks the expected
fingerprint immediately before atomic replacement. A concurrent owner edit is
preserved and leaves a recoverable pending migration. Rollback uses the same
replacement path. An unfinished rollback cannot accidentally resume forward
migration.

The rollback generation is now persisted in the database conversion transaction.
Previously, resuming after conversion could read a later generation and adopt
intervening durable writes as its rollback baseline. Recovery now refuses that
case, including a write followed by deletion. Existing unfinished migrations
without the new marker are accepted only when their generation proves no writes.

Fault checkpoints exercise the actual migration prefix through intent, both
backups, prepared journal, schema upgrade, conversion, configuration export and
completion. Each interruption resumes with one automatic-pause resume audit,
intact original backups and a valid rollback. Separate tests cover all three
rollback boundaries, concurrent file editing, shared writer locking and
post-conversion mutation refusal. An additional matrix upgrades every recognized schema (v0–v5), repeats the
upgrade, and restores its own original database/configuration. Fresh installation
and post-completion rollback guards retain their existing tests.

The intermittent gh cleanup test used the appearance of a fifth process as its
cleanup acknowledgement. That also depended on SQLite intent recording/fsync
and interpreter startup. A deterministic regression blocks the SQLite queue and
reproduces that witness timing out **after** the cancelled leader is reaped and
its permit is available. The corrected regression observes the actual semaphore
and verifies the leader no longer exists. It still checks that a stubborn child
retains the permit during its grace period, and retains the original three-second
cleanup deadline. Polling no longer busy-spins through synchronous file parsing.
This identifies and removes a false-positive measurement; it does not claim to
reconstruct the exact disk/scheduling delay from the earlier uninstrumented run.
No production cleanup grace or command deadline was increased.

Injected process-group EPERM now exercises fallback against a real owned child
and verifies its signal exit and reaping. Other signal errors remain visible;
missing groups do not trigger unrelated leader signals. Native macOS and remote
execution conformance still belong to deployment/platform validation.

## Validation

Final commands and counts are recorded in the
[implementation status](v0.4-implementation-status.md#recovery-and-replay-checkout-delivery-2026-09-29).
The full Rust gate includes architecture, migrations, replay and existing
process/socket/control tests. The corrected cleanup regression is also repeated
twenty times with its original deadlines.

The first retained-Python run had 388 passes and one host-probe timeout. A bounded
probe diagnostic reached `systemd_user_bus=unusable` and then blocked in the
inherited `ssh-add -l` call. Running the unchanged suite with `SSH_AUTH_SOCK`
unset passes all 389 cases. This changes only the test process environment;
it does not modify the owner's agent or credentials. The frozen probe and its
fingerprint remain unchanged.

Only this repository and its frozen `spec/` implementation were consulted.
No external reference repository or installed Slack daemon was used.
