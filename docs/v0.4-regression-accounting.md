# Step 2 regression accounting

Reviewed 2026-09-29. `tests/regression-map.json` is the machine-readable ledger for
all **389 frozen v0.3.11 Python cases**. Each case names a reviewed audit group,
its specific retention rationale, and the next verification gate. There are
**45 groups** with named Rust test references where applicable.

| Classification | Python cases | Meaning |
| --- | ---: | --- |
| Scoped Rust evidence | 172 | Supported projections or runtime behavior have named tests; complete differential parity has not been established. |
| Changed behavior | 168 | Named Rust tests cover the successor behavior; the ledger explains deliberate attention, authority, durability, protocol or confinement differences. |
| Python-only retention | 49 | Existing Python tooling/UI or an exact legacy/platform assertion stays retained for an explicit reason. |
| Total retained | 389 | No Python regression has been removed or declared fully replaced. |

The 49 Python-only cases are release tooling (35), documentation statistics and
probes (7), dashboard serving (3), the historical upgrade note (2), tiny-budget
`split_message` helper behavior (1), and reserved
Slurm transport (1). Dashboard is explicitly deferred, Slurm execution is out of
scope. Injected `killpg` EPERM now has scoped Rust evidence using a real owned
process; actual-platform conformance remains a deployment gate. Python
helpers and release/documentation scripts continue to be tested as Python.

The ledger also makes previously implicit differences explicit:

- F4's permanent canned blocked notices and name-lookup formatting are retained
  in Python. v0.4 records blocked notes and allows explicit new interactions under
  attention gates; blocked replies cannot satisfy asks.
- Automatic loop pauses become visible streak obligations. Owner pauses retain
  exclusive owner resume authority.
- Failed action repair is rejected atomically; ordinary unavailable decisions
  commit a blocked fallback and hold automatic due work for review.
- A recorded parent call by itself does not prove actor effects committed. Rust
  settles inbox/effects atomically and recovers incomplete claims.
- Deferred inbox items do not prevent owner controls and worker results from
  proceeding. Ambiguous sends never trigger an automatic resend.
- Strict protocol, identifier, output-size, filesystem and authentication checks
  intentionally reject some legacy permissive inputs.

`python scripts/verify_baseline.py` verifies immutable baseline fingerprints,
389 unique mapped cases, frozen test-function inventory, every audit-group link,
matching retention rationale, permitted next gates and actual named Rust **test**
functions. A helper function or nonexistent test cannot satisfy an evidence link;
unreferenced groups and stale primary evidence also fail verification.
`tests/test_regression_audit.py` injects malformed ledger entries to exercise these
checks. CI runs the verifier and regenerates the control/reply corpora to detect
fixture drift.

A named test is scoped evidence, not proof that every assertion or interleaving of
its Python case is identical. Retention accounting is complete for step 2, with
subsequent synthetic recovery/replay evidence recorded in
[v0.4 recovery verification](v0.4-recovery-verification.md). Native packaging,
historical captures and real-host conformance remain later gates. This ledger
neither retires the production Python
implementation nor enables active Rust CLI startup.
