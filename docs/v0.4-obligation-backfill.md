# Experimental historical obligation backfill

The Rust control client can preview and explicitly create obligations for retained
mentions that have no obligation record. Migration and startup never run backfill.
Use this against an experimental Rust service's authenticated owner control socket;
it does not require installing a live Slack daemon on the development machine.
The Python production CLI does not implement these commands.

Select a half-open range of source-message Unix timestamps: `since` is inclusive,
`until` is exclusive and cannot be in the future. Preview first:

```sh
cargo run --offline --bin fridica -- obligations --socket /path/to/control.sock \
  --backfill --since 1700000000 --until 1700086400
```

The response lists candidate event/thread IDs without message text. Preview creates
no obligations or posts; the control API still records its normal request/response
ledger. Selection is limited to the configured workspace/channels and existing
threads, excludes owner/self messages, closed/archived/cleaned threads and messages
at or before a thread's clean/reset boundary, and preserves owner-paused threads.
Existing obligations are excluded regardless of whether they are open or closed.
More than 1,000 candidates refuses the whole request; use a narrower time range.

Apply the selected time range with an explicit client ID:

```sh
cargo run --offline --bin fridica -- obligations --socket /path/to/control.sock \
  --backfill --since 1700000000 --until 1700086400 \
  --apply --client-id backfill-20260928-01
```

New obligations say **answer status requires owner review**. Historical posts alone
cannot prove that a particular mention was answered, so backfill never fabricates
an answered state or delivery evidence. Obligations start deferred until application
time plus `attention.mention_grace`; the normal scheduler may act when they become
due, subject to thread controls and observe-only. Applying backfill does not resume
an owner pause, enqueue duplicate historical messages or send posts itself.

Creation, mention flags, the audit and the idempotency record commit together.
Repeat the same client ID and request after an uncertain response to retrieve the
original result. Reusing that ID for a different time range or configured scope
is rejected. A new request still deduplicates on the original mention identity.
Preview and application select current retained data; a preview is not a frozen
snapshot of concurrently arriving history.

List obligations and close one that the owner has already handled:

```sh
cargo run --offline --bin fridica -- obligations --socket /path/to/control.sock
cargo run --offline --bin fridica -- obligations --socket /path/to/control.sock \
  --close 'backfill:mention:TTEAM:CROOM:1700000001.000001' \
  --reason 'Already handled before migration'
```

Closing records `owner_closed` and an audit atomically. It does not claim confirmed
answer delivery or cancel a previously queued post. Backfill and closure require
authenticated owner authority; neither a body field claiming to be the owner nor
an overseer/read-only capability grants access. Routes are `GET /obligations`,
`POST /obligations/backfill` and `POST /obligations/{id}/close`.
